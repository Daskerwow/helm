Как устроена библиотека

Helm — это предсказуемый state-менеджер, построенный вокруг одного центрального объекта — StateStore<S, E>. S — тип состояния, E — тип side-эффектов (событий, которые не являются частью состояния: навигация, снекбар, разовый тост).

Библиотека физически разделена на два независимых слоя, и это разделение — центральный архитектурный инвариант всего проекта:

Core package:helm/helm.dart

Чистый Dart. Ни одного импорта package:flutter. Работает в CLI, на сервере, в изоляте — где угодно, где есть Dart. Отвечает за диспатч команд, отмену, хранение и синхронную публикацию изменений.

  • StateStore — центральный объект
  • Команды: sync / async / stream, с эффектом и без
  • CancelToken, DispatchResult, Loadable
  • Internal-writers: цепочка декораторов вокруг commit()

Flutter Bridge package:helm/flutter.dart

Зависит от Core, но не наоборот. Строится строго на нативных примитивах Flutter — ChangeNotifier/ValueListenable/Listenable — без стороннего рантайма поверх Stream.

  • HelmFeature — глобально адресуемый ленивый токен фичи
  • HelmController — мост StateStore → ValueListenable
  • HelmBuilder/Selector/Listener/Consumer — виджеты-обёртки
  • feature.watch()/.select()/.effect() — hooks-подобный синтаксис
  • HelmComputed — производные значения из нескольких фич

state_access.dart

lib/src/core/state_access.dart

Базовые контракты доступа к состоянию — разделение прав "читать" / "писать" по принципу разделения интерфейсов (ISP). Именно эти интерфейсы получают команды вместо прямого доступа к Store.

interfaceIStateReader<S>

Право только на чтение состояния.

S get current;

Синхронный геттер текущего состояния. Передаётся наблюдателям и командам, которым не нужно писать — например, второй параметр execute() команд получает именно IStateReader, а не полный доступ к Store.

interfaceIStateWriter<S>

Право только на запись состояния.

void commit(S nextState);

Фиксирует новое состояние. Контракт гласит, что StateStore эмитирует обновление синхронно, в момент вызова — никакой буферизации через микрозадачу или Stream. Это гарантия согласованности: state и подписчики видят одно и то же в любой момент времени.

Именно этот интерфейс оборачивается декораторами GuardedWriter, EmittingWriter, TrackingWriter — паттерн Decorator, а не наследование, чтобы независимо комбинировать "публикацию", "защиту от коммита после отмены" и "группировку по итерациям потока".

interfaceIStateAccessor<S>

Полный доступ — объединение IStateReader и IStateWriter.

classStateAccessor<S> implements IStateAccessor

Тонкий адаптер IStateAccessor → IStateStorage, без бизнес-логики.

const StateAccessor(IStateStorage<S> storage);

Оборачивает конкретное хранилище (по умолчанию StateMemoryStorage) и просто делегирует current → storage.read(), commit → storage.write(). Единственный "мост" между абстрактным контрактом доступа и физическим хранением значения.

state_storage.dart

lib/src/core/state_storage.dart

Контракт синхронного физического хранилища состояния — точка расширения (Dependency Inversion), но не предназначена для персистентных асинхронных хранилищ напрямую.

interfaceIStateStorage<S>
S read(); void write(S state);

Намеренно примитивный контракт: только синхронное чтение/запись. Персистентные асинхронные хранилища (SharedPreferences, sqflite, Hive) не реализуют его напрямую — правильный паттерн: прочитать начальное значение асинхронно ДО создания StateStore, а запись на диск выполнять как побочный эффект в onChanged/внутри самой команды. Store — рантайм-состояние в памяти с быстрым синхронным доступом, а не ORM.

classStateMemoryStorage<S> implements IStateStorage

Реализация по умолчанию — хранение состояния прямо в поле объекта.

StateMemoryStorage(this._state);

Одно приватное мутируемое поле S _state. read() возвращает его, write() перезаписывает. Используется, если конструктору StateStore не передан кастомный storage.

equality.dart

lib/src/core/equality.dart

Готовые компараторы "состояние не изменилось" — нужны, когда S (или срез, выбранный selector) не имеет содержательного ==, например обычный мутируемый List/Set/Map. Тонкая обёртка над package:collection.

functiondefaultEquals<T>(T a, T b)
bool defaultEquals<T>(T a, T b) => a == b;

Компаратор по умолчанию — обычное структурное ==. Оформлен как top-level generic-функция (tear-off), а не как фабрика "функция → замыкание", чтобы defaultEquals<T> переиспользовалась без аллокации нового замыкания на каждый вызов конструктора StateStore/EmittingWriter/HelmComputed.

class · internal_FunctionEquality<T> implements Equality<T>

Адаптер обычной функции-компаратора к Equality<T> из package:collection.

equals

Делегирует переданной функции _equals.

hash

Всегда делегирует в Object.hashCode элемента, а не в переданный компаратор — он не участвует в сравнении коллекций (listEquals/mapEquals вызывают Equality.equals напрямую, не хешируя коллекцию целиком). Построить корректный хэш для двух объектов, равных по кастомному _equals, но не по ==, в общем случае невозможно без отдельной хэш-функции от пользователя.

isValidKey

Всегда true.

functionlistEquals<T>(List<T>? a, List<T>? b, {elementEquals})

Поэлементное сравнение двух списков без промежуточных Set/Map. Без такого компаратора Store/HelmComputed/HelmSelector считали бы новый список с теми же элементами "другим состоянием" при каждом коммите — лишние публикации и ребилды, потому что обычный List не переопределяет == содержательно.

Быстрый путь сперва проверяется identical(a, b), затем null-safety, а сама реализация — ListEquality из package:collection (пакет уже транзитивно тянется большинством Flutter-проектов, поэтому не добавляет нового следа в дереве зависимостей).

elementEquals — компаратор элементов, по умолчанию defaultEquals. Порядок важен: [1,2] != [2,1].

functionsetEquals<T>(Set<T>? a, Set<T>? b)

Сравнение множеств по содержимому, без учёта порядка вставки — обёртка над SetEquality.

functionmapEquals<K, V>(Map<K, V>? a, Map<K, V>? b, {valueEquals})

Сравнение по ключам и значениям, без учёта порядка вставки. valueEquals — компаратор значений (по умолчанию ==). Ключи всегда сравниваются через ==/hashCode — MapEquality по умолчанию использует DefaultEquality для ключей, кастомизируется только сравнение значений.

functiondeepEquals(Object? a, Object? b)

Рекурсивное сравнение "как есть" для значений с произвольной вложенностью List/Set/Map/Iterable (например, состояние, собранное из JSON). Делегирует в DeepCollectionEquality.

Не заменяет предметно-специфичный equals в общем случае: если у S есть содержательный == (data-класс, @immutable), он почти всегда быстрее и точнее. deepEquals пригождается, когда содержательного == нет и заводить его ради одного сравнения избыточно.

cancel_token.dart

lib/src/core/cancel_token.dart

Одноразовый токен отмены асинхронных/потоковых команд — центральный механизм защиты от гонок (race conditions), когда результат устаревшего запроса приходит после того, как его вытеснил новый.

enumCancelReason
superseded

Команда с тем же DispatchKeyed.dispatchKey запущена повторно — предыдущий вызов вытеснен.

userRequested

Явный вызов StateStore.cancel/cancelAll.

storeClosed

Store закрыт через StateStore.close.

classCancelToken

Проверяется командой после каждого await, перед каждым commit.

поле CancelReason? _reason;

Отсутствие причины = токен активен. isCancelled и reason — публичные геттеры поверх этого поля.

поле CallbackList<void Function()>? _onCancelListeners;

Список колбэков whenCancelled, создаётся лениво — подавляющее большинство токенов не имеет подписчиков на отмену, заводить под них список заранее незачем.

void cancel([CancelReason reason = userRequested])

Отменяет токен. Повторный вызов — no-op: причина не перезаписывается (первая причина отмены — окончательная). После установки _reason список колбэков вынимается из поля (_onCancelListeners = null) и вызывается через CallbackList.notify с изоляцией ошибок: упавший колбэк логируется debug-only через assert, но не мешает остальным whenCancelled-колбэкам и никогда не бросает исключение наружу.

void whenCancelled(void Function() callback)

Регистрирует колбэк, вызываемый ровно один раз в момент отмены — удобно, чтобы освободить внешний ресурс (сокет, таймер, подписку) без поллинга isCancelled. Если токен уже отменён — вызывается немедленно и синхронно. Можно регистрировать сколько угодно независимых колбэков — каждый вызывается ровно один раз, в порядке регистрации; падение одного не мешает остальным.

Двойная защита от гонок: команда сама должна проверять isCancelled перед коммитом, но Store дополнительно подстраховывает через GuardedWriter — коммит после отмены молча игнорируется, даже если команда забыла проверить токен.

dispatch.dart

lib/src/core/dispatch.dart

Типы, описывающие исходы и метаданные диспатча: как классифицировать команду, что прилетает в лог/middleware, и sealed-иерархия результата.

enumDispatchKind

{ sync, async, stream } — тип диспатча, для фильтрации/группировки в middleware и логах.

interfaceDispatchKeyed

Опциональный контракт: свой ключ группировки dispatch/cancel вместо значения по умолчанию (command.runtimeType).

Object get dispatchKey;

В Dart дженерики реифицированы: runtimeType уже учитывает типовые параметры (FetchCommand<User> и FetchCommand<Todo> — разные Type), коллизий между инстанциациями одного generic-класса нет. DispatchKeyed решает другую задачу: когда одна и та же инстанциация команды должна поддерживать несколько параллельных, не вытесняющих друг друга запусков — например, загрузка разных userId одним и тем же классом команды.

Ключ участвует в Map-поиске через ==/hashCode — используй значения с содержательным равенством (Record, String, int, enum). Свежесозданный Object() без переопределённого == равен только самому себе и превращает DispatchKeyed в бесполезную группировку "сам с собой".
interfaceDispatchLabeled
String get dispatchLabel;

Опциональное явное имя команды для логов/DevTools вместо runtimeType.toString(), которое в release-сборке минифицируется obfuscator'ом до бессмысленных a/b/c.

classDispatchEvent<S>

Снапшот исхода диспатча — эмитируется в addDispatchListener при любом исходе: успех, ошибка, отмена.

commandLabel

Имя команды — см. DispatchLabeled.

before / after

Состояние до и после выполнения. При ошибке/отмене без коммита after == before.

kind

sync/async/stream.

error

Исключение, если команда завершилась с ошибкой.

elapsed

Время выполнения. null для sync-команд (мгновенны) и когда никто не подписан на addDispatchListener — замер не делается впустую (см. Stopwatch в _runAsync).

cancelReason

Причина отмены, если команда была отменена.

bool get isSuccess => error == null && cancelReason == null; bool get isCancelled => cancelReason != null;
String toLogString({bool useEmoji = true})

Компактная строка для логов вида ✓ [async] FetchUserCommand (120ms). useEmoji: false переключает на ASCII-маркеры ([OK]/[FAIL]/ (cancelled)) для терминалов/парсеров без юникода.

sealed classDispatchResult<S>

Результат dispatch/dispatchWithEffect. Sealed-иерархия — исчерпывающий switch без риска пропустить исход.

final class DispatchSuccess<S> extends DispatchResult<S> { final S state; }

Команда выполнена успешно; state — состояние Store после выполнения.

final class DispatchFailure<S> extends DispatchResult<S> { final Object error; final StackTrace stackTrace; }

Команда завершилась необработанным исключением. Состояние могло измениться: любой commit, сделанный до исключения, уже применён и опубликован.

final class DispatchCancelled<S> extends DispatchResult<S> { final CancelReason reason; }

Команда отменена до завершения. Состояние могло измениться: коммиты до отмены уже применены — Store лишь гарантирует, что коммиты после отмены игнорируются.

state_command.dart

lib/src/core/state_command.dart

Контракты команд без side-эффекта (три вида: sync/async/stream) плюс набор готовых "коробочных" команд для типовых сценариев, чтобы не писать отдельный класс на каждую тривиальную мутацию.

interfaceISyncCommand<S>
S execute(S current);

Мгновенная синхронная мутация без IO и side-эффектов. Должна быть чистой функцией. Гарантированно выполняется атомарно: без await, без токена отмены.

interfaceIAsyncCommand<S>
Future<void> execute(IStateReader<S> reader, IStateWriter<S> writer, CancelToken cancel);

Единичное асинхронное действие без side-эффекта. Обязана проверять cancel.isCancelled перед каждым commit.

interfaceIStreamCommand<S>
Stream<void> execute(IStateReader<S> reader, IStateWriter<S> writer);

Подписка на внешний Stream, коммитящая каждое входящее значение. Store управляет жизненным циклом подписки: отписывается при close или при повторном dispatchStream с той же группой отмены (DispatchKeyed).

classSetStateCommand<S> implements ISyncCommand

Заменяет состояние на заранее известное значение next — без отдельного класса команды на каждую тривиальную мутацию: store.dispatchSync(SetStateCommand(FilterZone.all)).

classUpdateStateCommand<S> implements ISyncCommand

Вычисляет новое состояние из текущего чистой функцией update(S current) — типовой copyWith-подобный апдейт без отдельного класса.

classSetStateWithEffectCommand<S, E> implements ISyncSideEffect

Как SetStateCommand, но дополнительно эмитирует фиксированный effect.

classUpdateStateWithEffectCommand<S, E> implements ISyncSideEffect

Как UpdateStateCommand, но функция update сразу возвращает пару (состояние, эффект) — для случаев, когда эффект зависит от результата вычисления.

classLoadStateCommand<S> implements IAsyncCommand
execute(reader, writer, cancel) async { final next = await load(); if (cancel.isCancelled) return; writer.commit(next); }

Загружает состояние целиком через переданную функцию load и коммитит результат целиком. Проверяет отмену после await, перед коммитом — эталонный пример правильного использования CancelToken.

classEmitEffectCommand<S, E> implements ISyncSideEffect

Эмитирует side-эффект, не трогая состояние (возвращает (current, effect)) — навигация, диалог, аналитическое событие без изменения данных.

state_effect_command.dart

lib/src/core/state_effect_command.dart

Те же три вида команд (sync/async/stream), но каждая дополнительно возвращает side-эффект E — событие, не являющееся частью состояния.

typedefSyncSideEffectResult<S, E>
typedef SyncSideEffectResult<S, E> = (S next, E? effect);

Record-тип: атомарный результат sync-команды с эффектом. effect == null означает "эффект не эмитируется в этом выполнении".

interfaceISyncSideEffect<S, E>
SyncSideEffectResult<S, E> execute(S current);

Синхронная команда с атомарным возвратом нового состояния и опционального эффекта. Должна быть чистой функцией.

interfaceIAsyncSideEffect<S, E>
Future<E?> execute(IStateReader<S>, IStateWriter<S>, CancelToken);

Единичное асинхронное действие, возвращающее опциональный side-эффект (например, NavigateToHome при успешном логине). Как и любая async-команда — проверяет isCancelled перед каждым коммитом.

interfaceIStreamSideEffect<S, E>
Stream<E?> execute(IStateReader<S>, IStateWriter<S>);

Stream-команда, каждая итерация которой может обновить состояние и/или эмитировать side-эффект; null из итерации — эффекта в этот раз нет.

middleware.dart

lib/src/core/middleware.dart

Именованная, переиспользуемая альтернатива анонимному колбэку в addDispatchListener.

interfaceStoreMiddleware<S>
void onDispatch(DispatchEvent<S> event);

Вызывается после каждого диспатча — при успехе, ошибке и отмене, одинаково для sync/async/stream команд. Технически StoreMiddleware ничего не добавляет к возможностям Store сверх addDispatchListener — DispatchEvent уже несёт всё нужное для наблюдения "после факта". Ценность в форме: у объекта есть имя типа, жизненный цикл (можно хранить список активных middleware в DI-контейнере, включать/выключать по фиче-флагу), проще тестировать в изоляции, чем безымянное замыкание.

Helm намеренно не даёт middleware перехватывать/подменять команду или её результат до выполнения — это сломало бы гарантию "любой коммит публикуется синхронно и без исключений на пути между командой и подписчиками состояния".

onDispatch не должен бросать исключения: изоляция ошибок между слушателями защищает доставку остальным, но упавший middleware всё равно не выполнит свою работу для текущего события — рискованные операции (сетевой вызов аналитики) стоит оборачивать в собственный try/catch.

loadable.dart

lib/src/core/loadable.dart

Готовое состояние одного асинхронного ресурса — аналог AsyncValue<T> (Riverpod) / AsyncSnapshot<T> (Flutter), без зависимости на них. Можно использовать как весь S Store'а либо как поле внутри более сложного состояния.

sealed classLoadable<T>

Четыре состояния ресурса: не запрашивался / грузится / загружен / упал с ошибкой.

const factory Loadable.idle() = LoadableIdle<T>; const factory Loadable.loading([T? previous]) = LoadableLoading<T>; const factory Loadable.data(T value) = LoadableData<T>; const factory Loadable.error(Object error, [StackTrace? st, T? previous]) = LoadableError<T>;

Четыре фабричных конструктора. previous у loading/error — последнее успешно загруженное значение: позволяет показать старые данные поверх спиннера (pull-to-refresh не обнуляет экран).

bool get isLoading => this is LoadableLoading<T>; bool get isError => this is LoadableError<T>;
T? get valueOrNull

Последнее известное значение — из data либо "протянутое" previous у loading/error. null, если значения не было ни разу (idle).

почему не growable List<T>

Слушатели хранятся не как обычный растущий List<T>, а вручную — fixed-length List<T?> + отдельный счётчик _count. Тот же приём, что и в ChangeNotifier Flutter SDK: это горячий путь (вызывается на каждый commit/notifyListeners), и накладные расходы growable-обёртки поверх fixed-length массива на нём заметны.

компактизация с гистерезисом

Если живых элементов ≤ половины текущей ёмкости массива — выделяется новый массив точного размера (иначе список рос бы бесконечно после разового всплеска подписчиков и никогда не сжимался обратно). Иначе — компактизация НА МЕСТЕ через попарные свопы, без единой аллокации.

реентрантность

add/remove/clear безопасны для вызова изнутри notify — типичный сценарий, когда слушатель сам меняет состав подписчиков (например, реагирует на событие закрытием всего источника публикаций). Во время активной итерации удаления не сдвигают массив физически (это сломало бы индексы цикла), а помечают слот null (tombstone); реальная уборка происходит в конце самого внешнего notify.

изоляция ошибок — параметр onError

По умолчанию исключение из слушателя внутри notify не перехватывается — прерывает текущий проход и летит вызывающему коду (тот же контракт, что и раньше). Это осознанное поведение по умолчанию: молчаливое поглощение чужого исключения без адресата — подмена семантики, а не перформанс-оптимизация. Если передан onError, notify переключается в изолированный режим: исключение из одного слушателя перехватывается, передаётся в onError, а проход продолжается для остальных. Так Store защищает свои каналы — один "плохой" слушатель (например, упавший аналитический хук) не блокирует доставку события остальным.

Сжимает backing-массив только если живых элементов после удаления ≤ половины его длины — иначе просто сдвигает хвост на месте, без реаллокации. Без порога список рос бы, но никогда не уменьшался, а с ним — не дёргался бы grow/shrink на каждый цикл add/remove одного элемента у границы.

Убирает первое вхождение (сравнение по ==). Не найден — no-op, безопасно для повторного вызова. Если вызвано во время активной итерации (_notificationCallStackDepth > 0) — слот лишь помечается null и увеличивается _reentrantlyRemoved; иначе — немедленно _removeAt.

Убирает всех слушателей; безопасен для вызова изнутри notify тем же способом, что и remove (реентрантная пометка либо немедленный сброс).

Вызывает callback для каждого текущего слушателя. Слушатели, добавленные во время вызова, в этот проход не попадают (цикл ограничен снапшотом end = _count, зафиксированным до начала итерации); удалённые во время вызова — попадают, но пропускаются (listener == null). Broadcast-Stream состояний поверх addOnChanged — для кода, ожидающего Stream (StreamBuilder, await for). В отличие от effects, каждый новый подписчик сразу получает текущее состояние первым событием, а дальше — каждое изменение. Без этого поздний подписчик (типичный сценарий: StreamBuilder создаётся уже после первых изменений Store) не увидел бы актуальное состояние вплоть до следующего коммита — источник "пустого экрана до первого чужого действия".

Реализовано через Stream.multi: колбэк выполняется заново для каждого отдельного подписчика, поэтому "seed" не смешивается между разными слушателями брошенного broadcast-потока. Если Store уже закрыт — контроллер сразу закрывается, ничего не эмитируя.

Stream<E> get effects

Broadcast-Stream side-эффектов поверх addOnEffect. Чистый поток событий: в отличие от states, не несёт "текущего значения" и ничего не отправляет новому подписчику при подписке. Контроллер — обычный StreamController.broadcast(sync: true), создаётся лениво.

Синхронное чтение и debug

S get state => _accessor.current;
bool get isClosed => _closed;
void debugResetForTesting(S state)

Принудительно заменяет состояние, минуя обычный dispatch-цикл — только для тестов. Без DispatchEvent, без проверки isClosed. Публикует изменение, если значение реально отличается. Префикс debug — как debugPrint/debugDumpApp в самом Flutter SDK: сигнализирует "не для продакшен-кода", делая случайное использование в обычной команде/сервисе заметным при code review и легко находимым поиском по имени.

Stream dispatch

void dispatchStream(IStreamCommand<S> command)

Подписывается на Stream-команду без side-эффектов. Если команда с той же группой отмены уже активна — предыдущая подписка отменяется первой. После close — no-op.

void dispatchStreamWithEffect(IStreamSideEffect<S, E> command)

Та же семантика отмены предыдущей подписки; дополнительно каждый ненулевой элемент потока эмитируется через _listeners.notifyEffect.

void _dispatchStream(Object command, Stream<void> Function(TrackingWriter<S>) execute)

Общее ядро обоих публичных методов: отменяет предыдущую подписку той же группы (_cancelStreamSubscription(key, superseded)), заводит общий TrackingWriter поверх свежего EmittingWriter и подписывается на поток, который строит execute поверх этого writer'а. Разница между двумя публичными методами — только в том, публикует ли execute side-эффект на каждый элемент потока.

Async dispatch

Future<DispatchResult<S>> dispatch(IAsyncCommand<S> command)

Если команда с той же группой отмены уже выполняется — предыдущая отменяется с CancelReason.superseded. После close немедленно возвращает DispatchCancelled(storeClosed), не запуская команду.

Future<DispatchResult<S>> dispatchWithEffect(IAsyncSideEffect<S, E> command)

Как dispatch, но с side-эффектом.

Future<DispatchResult<S>> _dispatchAsync(Object command, execute)

Общее ядро обоих публичных методов: строит защищённый от коммитов-после-отмены writer (GuardedWriter поверх EmittingWriter, через _guardedWriter) и прогоняет его через _runAsync.

Sync dispatch

DispatchResult<S> dispatchSync(ISyncCommand<S> command)

Выполняется мгновенно, не может быть отменена. После close немедленно возвращает DispatchCancelled(storeClosed).

DispatchResult<S> dispatchSyncWithEffect(ISyncSideEffect<S, E> command)
DispatchResult<S> _dispatchSyncInternal(Object command, run)

Общее ядро: если Store закрыт — сразу DispatchCancelled; иначе прогоняет через _runSync, внутри которого run() вызывает command.execute и коммитит результат в _accessor.

Управление жизненным циклом

void cancel<U>() => cancelKey(U);

Отменяет активную async-команду по типу U — работает для команд без собственного DispatchKeyed.dispatchKey (обычный случай, когда группа отмены — runtimeType).

void cancelKey(Object key)

Отменяет по явному ключу — см. DispatchKeyed.

void cancelAll()

Отменяет все активные async-команды. Уже завершённые не затрагиваются.

void cancelStream<U>() => cancelStreamKey(U); void cancelStreamKey(Object key)

Отменяет активную stream-подписку по типу/ключу. Как и отмена async-команды, эмитирует DispatchEvent с cancelReason: userRequested.

void close()

Освобождает все ресурсы: отменяет активные async-команды и stream-подписки (с причиной storeClosed), снимает всех слушателей (_listeners.clear()), закрывает все контроллеры states/effects. Повторный вызов — no-op. После вызова все dispatch*-методы возвращают DispatchCancelled(storeClosed) (или ничего не делают для Stream-варианта), не бросая исключений — это позволяет безопасно вызывать close из владельца жизненного цикла даже если где-то ещё "в полёте" остался вызов dispatch.

Приватное ядро — оркестрация

EmittingWriter<S> _emittingWriter() => EmittingWriter<S>(_accessor, _listeners.notifyChange, _equals);

Собирает стандартный писатель "закоммитил → опубликовал" — общая точка входа для _dispatchAsync (дополнительно обёрнутый в GuardedWriter) и _dispatchStream (дополнительно обёрнутый в TrackingWriter).

GuardedWriter<S> _guardedWriter(CancelToken token, String label)

EmittingWriter, защищённый от коммитов после отмены токена — то, что нужно любой async-команде.

Object _keyOf(Object command) => command is DispatchKeyed ? command.dispatchKey : command.runtimeType;
String _labelOf(Object command) => command is DispatchLabeled ? command.dispatchLabel : command.runtimeType.toString();
DispatchEvent<S> _buildEvent({label, before, kind, elapsed, error, cancelReason})

Собирает DispatchEvent, беря after всегда из актуального _accessor.current на момент вызова.

Future<DispatchResult<S>> _runAsync(Object key, String label, _AsyncBody<E> body)

Единое ядро для всех async-диспатчей. Порядок действий:

  1. token = _acquireToken(key) — отменяет предыдущий токен группы, создаёт новый.
  2. Замеряет время только если есть хотя бы один слушатель dispatches (_listeners.dispatches.isEmpty ? null : Stopwatch()..start()) — elapsed не считается впустую, если его некому показать.
  3. Вызывает body(token). Публикация состояния уже произошла синхронно внутри EmittingWriter на каждый commit — дополнительная эмиссия здесь не нужна ни при каком исходе.
  4. Если токен отменён к концу выполнения — эмитирует DispatchEvent с cancelReason и возвращает DispatchCancelled.
  5. Иначе — эмитирует эффект (если есть), затем DispatchEvent успеха, возвращает DispatchSuccess.
  6. При исключении — notifyError, затем DispatchEvent с ошибкой, возвращает DispatchFailure.
  7. finally: _releaseToken(key, token) — убирает токен из реестра, если он не был заменён новым.
DispatchResult<S> _runSync(String label, _SyncBody<E> body)

Единое ядро для sync-диспатчей. Sync-команды атомарны (чистая функция → один коммит), поэтому исключение внутри body гарантированно происходит до коммита. После успешного body() — _publishIfChanged(before), эмиссия эффекта и DispatchEvent.

void _subscribeStream(key, label, Stream<void> stream, TrackingWriter<S> writer)

Общая логика подписки на stream-команды. Эмитирует DispatchEvent только на итерациях, где команда реально закоммитила ЧТО-ТО ОТЛИЧНОЕ от состояния на начало итерации (по _equals) — публикация состояния в addOnChanged от этого не зависит, она уже сделана EmittingWriter на каждый отдельный коммит по тому же компаратору.

writer.hasChanged сам по себе фиксирует лишь факт вызова commit хоть раз за итерацию — не то же самое, что "состояние реально другое": EmittingWriter может не опубликовать коммит, если _equals(next, last), а TrackingWriter всё равно отметит hasChanged = true. Без явной проверки !_equals(...) в лог утекали бы "пустые" stream-события, где before == after по собственному компаратору Store.

Команда могла синхронно закоммитить до подписки на поток (например, начальный Loadable.loading в WatchCommand) — публикация уже произошла, здесь этот "нулевой" цикл логируется отдельно от первого элемента потока. Ошибки потока (onError подписки) идут в notifyError + DispatchEvent, но не в канал effects — тот только для side-эффектов команды. cancelOnError: false: ошибка одного элемента не рвёт подписку целиком.

void _logStreamCycle(String label, TrackingWriter<S> writer)

Закрывает один цикл "before → after": сбрасывает writer и, если logStreamEvents включён и состояние реально изменилось, публикует DispatchEvent.

void _cancelStreamSubscription(Object key, CancelReason reason)

Отменяет активную подписку по ключу и эмитирует DispatchEvent с соответствующим CancelReason — тот же контракт, что и у отмены async-команд в _runAsync. Без этого addDispatchListener вообще не видел бы отмену/вытеснение stream-команд — асимметрия с async-путём, где DispatchCancelled виден и через возврат dispatch, и через addDispatchListener. No-op, если по key нет активной подписки.

void _publishIfChanged(S before)

Публикует состояние, если оно реально изменилось относительно before — используется _runSync и debugResetForTesting, которые делают ровно один коммит. Async/Stream-диспатчи публикуют на каждый отдельный коммит через EmittingWriter напрямую, эта функция им не нужна.

CancelToken _acquireToken(Object key)

Отменяет предыдущий токен той же группы (superseded) и создаёт новый, немедленно сохраняя его в реестре.

void _releaseToken(Object key, CancelToken token)

Удаляет токен из реестра, только если он всё ещё тот же самый объект, что был выдан (_cancelTokens[key] == token) — если его успели заменить более новым вызовом, чужой токен не трогается.

Довершает инициализацию — вешает слушатель и подписывается на feature.lifecycle. Реализация для полной подписки: любое изменение controller зовёт _onChanged (обычно element.markNeedsBuild). При смене контроллера тоже дёргает _onChanged — новый Store мог стартовать с другого состояния, нужен немедленный ребилд.

internal_SelectBinding<S, E, R> extends _FeatureBinding
_SelectBinding(super.feature, this.selector, this._onChanged) { _value = selector(controller.state); start(); } R Function(S) selector; // переприсваивается на каждый вызов select() late R _value; R get value => _value;
void _listener() { final next = selector(controller.state); if (next != _value) { _value = next; _onChanged(); } }

Перестраивает только когда результат селектора реально изменился.

void resync()

Синхронно пересчитывает значение по актуальному selector — вызывается сразу после переприсваивания selector в HelmFeatureReactive.select, до возврата значения вызывающей стороне. Без этого, если selector поменялся между билдами (замкнул новую переменную из внешнего build), _value оставался бы устаревшим до следующего изменения состояния фичи. Не вызывает _onChanged — мы уже внутри текущего build(), повторный markNeedsBuild() здесь не нужен.

_EffectBinding(super.feature, this.effect) { start(); WidgetsBinding.instance.addPostFrameCallback((_) { if (_disposed || _initialCallDone) return; _initialCallDone = true; effect(controller.state); }); }

Первый вызов — после текущего кадра, а не синхронно во время build(), как и эффекты в hooks-библиотеках.

void Function(S) effect; // переприсваивается на каждый вызов effect() bool _disposed = false; bool _initialCallDone = false;

_disposed защищает от вызова на уже отвязанном биндинге, если виджет размонтирован до конца кадра (например, навигация pop сразу после push) — без этой проверки callback всё равно выполнился бы поверх уже освобождённых ресурсов.

_initialCallDone защищает от двойного вызова: если lifecycle фичи сработал (overrideWith/принудительный dispose) раньше, чем успел выполниться post-frame callback, onControllerSwapped уже вызвал effect с актуальным состоянием нового контроллера — сам post-frame callback в этом случае должен стать no-op, а не позвать effect() второй раз тем же кадром с тем же (или уже следующим) состоянием.

mixinHelmReactiveElement on ComponentElement

Element-миксин, резолвящий feature.watch()/.select()/.effect().

почему без "порядка вызовов", в отличие от классических хуков

Классические хуки индексируют состояние по порядковому номеру вызова внутри build() — useState внутри if/цикла ломает всё. Здесь этой проблемы нет: у каждого биндинга уже есть стабильный между билдами ключ — сам объект HelmFeature (обычно top-level final). Биндинги хранятся в Map, поэтому feature.watch() можно звать условно, в цикле, где угодно; единственное, что нужно проговорить явно — Object key при нескольких разных биндингах одного вида на одной фиче в одном виджете.

static HelmReactiveElement? _current; final Map<_BindingKey, _Binding> _bindings = {}; final List<Set<_BindingKey>> _seenStack = []; final List<Set<_BindingKey>> _setPool = [];

_current — статический указатель на элемент, чей build() выполняется прямо сейчас; через него feature.watch() находит "свой" элемент без явного context.

_seenStack — стек наборов "увиденных в текущем build()" ключей: один элемент на каждый вложенный/повторный вызов build (устойчивость к reassemble()/hot reload, который может вызвать build() того же Element не строго последовательно).

_setPool — пул уже использованных (очищенных) наборов для _seenStack — без него каждый build аллоцировал бы новый <_BindingKey>{}. Для виджета, перестраивающегося внутри анимации (60 раз в секунду), это 60 лишних аллокаций в секунду на виджет. Сет из пула переиспользуется между билдами; новый выделяется только при глубокой реентрантности, когда пул пуст.

B _bindingFor<B extends _Binding>(_BindingKey key, B Function() create)

Регистрирует key в верхнем наборе _seenStack, затем возвращает существующий биндинг из _bindings либо создаёт новый через create() и сохраняет. assert(_seenStack.isNotEmpty, ...) — защита от вызова watch/select/effect вне build().

@override Widget build()

Сохраняет предыдущий _current, выставляет себя текущим, достаёт (или создаёт) пустой набор seen из пула, кладёт его в стек, вызывает super.build() (реальный build() виджета), в finally: снимает набор со стека, восстанавливает _current, зовёт _disposeUnseenBindings(finished), очищает набор и кладёт его обратно в пул.

void _disposeUnseenBindings(Set<_BindingKey> seen)

Удаляет из _bindings и вызывает dispose() на всех биндингах, чей ключ не встретился в текущем проходе build() — биндинги, не вызванные в очередном build() (например, условный watch() внутри if, который в этот раз не сработал), автоматически освобождаются сразу после него — без утечек и ручного управления.

@override void unmount()

При размонтировании элемента — dispose() на всех оставшихся биндингах, затем очистка карты.

function · internal_requireElement()

Возвращает HelmReactiveElement._current, с assert-сообщением, что feature.watch()/.select()/.effect() можно вызывать только внутри build() виджета, унаследованного от HelmWidget/StatefulHelmWidget. Вне build() — используй feature.value/.read()/.listen() напрямую.

extensionHelmFeatureReactive<S, E> on HelmFeature<S, E>

Короткий реактивный синтаксис прямо на токене фичи. Работает только внутри build() HelmWidget/StatefulHelmWidget.

S watch({Object? key})

Подписка на весь S + ребилд при каждом изменении — аналог HelmBuilder. Находит текущий элемент через _requireElement(), строит _BindingKey(this, watch, key), получает/создаёт _WatchBinding (с колбэком element.markNeedsBuild), возвращает .value. key нужен, только если на одной фиче зовётся несколько независимых watch() в одном виджете — на практике почти никогда.

R select<R>(R Function(S) selector, {Object? key})

Точечная подписка по срезу состояния (==) — аналог HelmSelector. Получает/создаёт _SelectBinding, переприсваивает его selector (чтобы замыкание всегда было свежим), зовёт binding.resync() — пересчитывает немедленно, и возвращает .value.

key обязателен, если на одной фиче вызывается несколько разных select() в одном виджете — иначе они делят биндинг и видят только последний вызванный selector:
final title = documentFeature.select((s) => s.title, key: #title);
final words = documentFeature.select((s) => s.body.length, key: #words);
void effect(void Function(S) callback, {Object? key})

Побочный эффект на каждое изменение состояния — аналог HelmListener, но по состоянию, а не по эффектам; не вызывает ребилд. Первый вызов — сразу после текущего кадра, последующие — на каждое изменение. Получает/создаёт _EffectBinding, переприсваивает его effect.

S read() => value;

Синхронное чтение без подписки — алиас value, для симметрии с watch. Можно вызывать откуда угодно, не только из build().

lib/flutter.dart — точка входа Flutter-моста

Barrel-файл моста: экспортирует helm_builder.dart, helm_computed.dart, helm_controller.dart, helm_feature.dart, helm_loadable.dart, helm_reactive.dart. dispatch_proxy.dart и binding_utils.dart намеренно не экспортируются напрямую — это внутренние утилиты, используемые остальными файлами моста, а не публичный API.

Какой API выбрать (памятка из докстринга файла):
  • весь ребилд по всему состоянию → HelmBuilder / feature.watch()
  • ребилд по срезу → HelmSelector / feature.select()
  • из нескольких фич сразу → HelmComputed
  • вне build() → feature.value / .listen()
Все четыре виджет-обёртки (HelmBuilder/HelmSelector/HelmListener/HelmConsumer) и три reactive-метода (watch/select/effect) — это один и тот же внутренний механизм подписки в двух разных синтаксисах (явный StatefulWidget вокруг дерева vs. вызов прямо в build()), а не два независимых способа решить одну задачу.
